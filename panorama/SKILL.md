# numas 全景图插件（numas.panorama）

打开 `*.pano` / `*.panorama` 数据文件，在 IDE 里渲染成可缩放、可拖拽编辑的架构图。
改动自动写回文件，不需要手动保存。

## 一、能做什么

**在 IDE 里打开 `.pano`（插件形态）**

- 双击文件即在 IDE 里打开成图（不是文本编辑器）
- 拖节点、改大小、改标题、加删节点
- 拖出连线、改连线端点、加标签
- 标记箭头（条件分支）与虚线（可选/非主链路）
- 缩放、适应窗口、居中
- **窗口/分栏变化后自动适配**：整图重新缩放以完整可见；若面板太窄，会停在可读比例并居中，靠拖动画布查看
- **手动缩放或拖动画布后不再自动适配**，点「适应」恢复
- 改动 600ms 后自动写回文件
- **悬停节点**：弹出说明卡片（popover）讲清这个节点——名字/副标题、所属层、在链路中的角色、**意图（为什么存在、想达成什么）**、上下游各是谁（含调用方式）、在运行模式中的位置；同时点亮该节点参与的链路，流动点沿链路移动；底部状态栏同步显示同一段说明。卡片为半透明毛玻璃，配色跟随页面主题

**打开 `index.html`（静态预览形态）**

- 只做高亮：悬停点亮相关节点与连线
- **没有**流动动画（无移动的点），**没有**说明卡片与自动解释（状态栏只显示「标题 · 副标题」）
- 改动存浏览器草稿，点「保存」才写回文件

> 两种形态能力不同：需要悬停解释与流动动画，用插件打开 `.pano`。

## 二、怎么打开

| 方式 | 操作 |
| --- | --- |
| 双击文件 | 在资源管理器里双击 `*.pano` / `*.panorama`，默认就用全景图打开 |
| 命令面板 | `Numas: 打开全景图` |
| 右键菜单 | 在 `.pano` 文件上右键 →「打开全景图」 |

前提：文件后缀是 `.pano` 或 `.panorama`，内容是合法 YAML（JSON 也能读）。

## 三、界面与操作

| 操作 | 效果 |
| --- | --- |
| 单击节点 | 选中，出现 8 个缩放手柄 |
| 拖动节点 | 移动，连线自动重算正交路径 |
| 拖手柄 | 改宽高 |
| 双击节点 | 就地改标题 / 副标题 |
| 悬停节点四边中点 | 出现小圆点，拖出即新建连线 |
| 拖连线端点 | 改接入的节点 / 边 / 位置（保持垂直于边） |
| 双击连线 | 就地改标签 |
| 单击连线 | 出现工具条：箭头 / 虚线 / 自动 / 删除 |
| 选中节点后 Delete | 删除节点及其连线 |
| 滚轮 / 底部按钮 | 缩放、适应窗口、居中 |
| 顶部图例 | 由 `bands` 自动生成，不用手画 |

## 四、文件格式

```yaml
title: ''
subtitle: ''
canvas:
  w: 1600
  h: 900
nodeHeight: 72
bands:
  - id: app
    label: webapp
    color: '#58a6ff'
nodes:
  - id: start
    band: app
    title: 开始
    sub: 副标题
    x: 120
    'y': 160
    w: 200
    h: 72
edges:
  - from: start
    to: end
    url: 连线上的文字
```

| 层级 | 字段 | 必填 | 说明 |
| --- | --- | --- | --- |
| 根 | `canvas.w` / `canvas.h` | 是 | 画布逻辑尺寸，影响「适应/居中」 |
| 根 | `nodeHeight` | 否 | 新节点的默认高度，缺省 72 |
| 根 | `title` / `subtitle` | 否 | 目前只存不显示，留空即可 |
| band | `id` / `label` / `color` | 是 | 层：图例文字与颜色（`#rrggbb`），节点按 `band` 取色 |
| node | `id` / `band` / `title` | 是 | `id` 唯一，被连线引用 |
| node | `sub` | 否 | 副标题 |
| node | `x` / `y` / `w` / `h` | 是 | 左上角坐标与宽高（px） |
| edge | `from` / `to` | 是 | 两端节点 id |
| edge | `url` | 否 | 连线上的标注文字（字段名叫 url，实际是任意文本） |
| edge | `sSide` / `tSide` | 否 | 接入边：`top` `right` `bottom` `left` |
| edge | `sRatio` / `tRatio` | 否 | 接入点在边上的位置，0–1 |
| edge | `arrow` / `dashed` | 否 | `true` 画箭头 / 虚线 |
| edge | `sourcePort` / `targetPort` | 否 | 编辑器自动维护，手写一般不需要 |

不写 `sSide`/`tSide` 时，编辑器按几何自动选最近的边；想固定走线再手工写。

## 五、从零画一张

1. 新建 `xxx.pano`，先写 `canvas` 和 `bands`（决定配色与图例）
2. 按层摆节点：同一层的 `y` 对齐，横向留 40px 以上间距
3. 加连线：只写 `from` / `to` / `url`，走向交给编辑器
4. 只有**条件分支**才加 `arrow: true`；可选路径用 `dashed: true`
5. 在 IDE 里打开，按需拖拽微调；改动会自动保存

坐标不用一次到位——先摆大概位置，剩下的在界面里拖。

## 六、保存与同步

- 任何改动后 **600ms 自动写回**文件，不用点保存
- 文件被外部修改时，编辑器会把新内容推回视图重新渲染
- 文件格式统一写成 YAML（原有 JSON 文件也能打开，保存后变 YAML）

## 七、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 打开是文本不是图 | 后缀不是 `.pano` / `.panorama`；或扩展未安装，见安装说明 |
| 打开一片空白 | YAML 解析失败：检查缩进、是否混入 tab、是否用了中文冒号 |
| 节点没颜色 / 图例少一项 | `node.band` 引用了不存在的 `band.id` |
| 连线指向空气 | `edge.from` / `edge.to` 拼错，或节点 id 改过没同步 |
| 线斜着走 | 手工写了 `sSide` 后节点位置又变了；删掉该字段让编辑器重算 |
| `y` 字段被写成 `'y'` | 正常：YAML 解析器会把 `y` 加引号，两种写法都能读 |

## 八、一份可以直接用的骨架

```yaml
title: ''
subtitle: ''
canvas: { w: 1200, h: 700 }
nodeHeight: 72
bands:
  - { id: app,  label: webapp,       color: '#58a6ff' }
  - { id: edge, label: 接入层服务,    color: '#fbbf24' }
  - { id: svc,  label: 应用层服务,    color: '#f472b6' }
  - { id: infra, label: 基础设施层服务, color: '#34d27b' }
nodes:
  - { id: web,     band: app,   title: webapp,        sub: 浏览器 · 前端,   x: 480, 'y': 60,  w: 240, h: 72 }
  - { id: ingress, band: edge,  title: nginx-ingress, sub: 统一入口,        x: 200, 'y': 220, w: 800, h: 72 }
  - { id: api,     band: svc,   title: api-server,    sub: 业务逻辑,        x: 200, 'y': 400, w: 220, h: 72 }
  - { id: db,      band: infra, title: postgres,      sub: 主库,            x: 200, 'y': 560, w: 220, h: 72 }
edges:
  - { from: web,     to: ingress, url: example.com }
  - { from: ingress, to: api,     url: /api/* }
  - { from: api,     to: db,      url: 读写 }
```

拷这份改成自己的结构即可：先改 `bands` 定配色，再改 `nodes` 摆位置，最后改 `edges` 连关系。
坐标不必一次到位，打开后在界面里拖更省事。

## 九、交付前自检

按顺序做三步，缺一步都可能交付一张"读不懂"的图。

### 1) 结构校验（数据层）

```bash
node scripts/check.mjs <文件.pano>
```

拦这些：字段缺失、`id` 重复、`band` 引用不存在、连线两端不存在、`sSide`/`ratio` 非法、节点越界或重叠、**同一对节点出现两条边**、节点缺 `title`/`band`、边缺语义标签。
`PASS` = 结构上能被插件正常打开并被读懂；`FAIL` 会指出具体节点/边。

### 2) 悬停自检（渲染层）

在 IDE 里打开 `.pano` → 打开开发者工具控制台 → 粘贴 [`scripts/hover-check.js`](scripts/hover-check.js) → 执行：

```js
await panoHoverCheck()   // => { pass: true, failures: [], rows: [...] }
```

逐节点断言：流动点存在且在动、无接缝跳变、高亮成链且有压暗对比、状态栏解释至少三段并含角色判断。

### 3) 人眼确认（观感）

管线正交、标注不重叠、层颜色能区分、闭环看得出"走出去又回来"。校验器管不了的，只能看。

## 十、让图更容易读懂（建议，不是硬性要求）

插件不会强制这些，但按下面写，别人（和 AI）更容易读懂你的图。

### 建议一：一条双工连接只画一条边

同一条双向连接（隧道、长连接）两个方向走的是同一份数据通道。不要为「回程」再加一条 `B → A`：

- 画两条会在图上出现两条重合/并行的线，读者分不清哪条是主要路径；
- 结构校验会直接拦下来（见第九节第 1 步）。

### 建议二：边标签写「动作」，而不是只写地址

| 写法 | 读者能获得的信息 |
| --- | --- |
| `注册·激活`、`bind · 出站`、`隧道 · dial`、`已存在 → 路由` | 这条线做什么、谁发起 |
| `ide.example.com`、`*.sandbox.example.com` | 只有 host；如果这张图讲的就是"按域名分发"，这样写也可以 |
| 空标签 | 读者无法判断这条线是路由、调用还是调度 |

判断方法：**换个人只看这条线的两端和标签，能不能说出"发生了什么"**。不能就补动作。

### 建议三：悬停时能讲清这个节点

插件会从结构推导解释，并用**卡片**（悬停时弹出）+ 状态栏两处展示：层、角色、上下游、所属链路。所以只要节点有 `title`、`band`，边有标签，解释就有内容；缺 `band` 时结构校验会报错——因为讲不出它在哪一层。

### 建议四：闭环要闭合

链路上节点与边同时点亮、流动点连续跑完全程。若看到"点跑到一半就消失/跳回"，说明图里该闭合的地方缺一条边（而不是动画坏了）。

### 可验证的部分

| 验证什么 | 用什么 | 能拦住的问题 |
| --- | --- | --- |
| 结构是否能被正常打开并读懂 | `node scripts/check.mjs <file>` | 字段缺失、引用不存在、节点越界/重叠、同一对节点两条边 |
| 悬停是否真的在动、链路是否成环 | `scripts/hover-check.js` → `await panoHoverCheck()` | 点不动、跳变、链路碎、解释退化成标题 |
| 观感（走向、留白、颜色对比） | 人眼看 | 校验器管不了 |

> 上面两条命令是**可复现**的；除此之外的"读不读得懂"，只能由看图的人判断，本文不给出硬指标。
