# numas 全景图（numas-panorama）

numas 的 `numas.panorama` 插件把 `*.pano` / `*.panorama` 文件渲染成可缩放、可编辑的架构全景图。
**交付物是一个数据文件**，不是图片、不是 HTML。写对了双击就能出图。

## 一、何时用

- 用户要画/改「系统全景图、架构总览、部署拓扑」
- 要产出 `*.pano` / `*.panorama` 文件给 numas 打开
- 已有的 `.pano` 需要调整节点、连线、分层

不适用：需要静态图片（用截图）、需要交互式网页（另做）。

## 二、文件格式（YAML）

```yaml
title: ''
subtitle: ''
canvas:
  w: 1600
  h: 900
nodeHeight: 72
bands:
  - id: local
    label: 本地服务
    color: '#c084fc'
nodes:
  - id: local
    band: app
    title: 本地模式
    sub: 托管在本地沙箱内
    x: 130
    'y': 100
    w: 146
    h: 72
edges:
  - from: local
    to: ingress
    url: ide.example.com
```

JSON 也能被读取（文件以 `{` 或 `[` 开头时走 JSON 解析），但插件保存时**统一写 YAML**。

### 字段表

| 层级 | 字段 | 必填 | 说明 |
| --- | --- | --- | --- |
| 根 | `title` / `subtitle` | 否 | 目前只存不用，留空字符串 |
| 根 | `canvas.w` / `canvas.h` | 是 | 画布逻辑尺寸，`适应` 与 `居中` 按它算；常用 1600×900 |
| 根 | `nodeHeight` | 否 | 默认节点高度，缺省 72；新拖出的节点用它 |
| band | `id` | 是 | 唯一，被 `node.band` 引用 |
| band | `label` | 是 | 图例文字（图例自动生成，不要手画） |
| band | `color` | 是 | `#rrggbb`，节点描边/文字/连线颜色都由它派生 |
| node | `id` | 是 | 唯一，被 `edge.from` / `edge.to` 引用 |
| node | `band` | 是 | 所属层，决定颜色 |
| node | `title` | 是 | 主标题 |
| node | `sub` | 否 | 副标题，可为空串 |
| node | `x` / `y` | 是 | 左上角坐标（画布坐标） |
| node | `w` / `h` | 是 | 宽高，px |
| edge | `from` / `to` | 是 | 两端节点 id，不能自环 |
| edge | `url` | 否 | 连线上的标注文字（这个名字是历史包袱，装的是**任意标签**） |
| edge | `sSide` / `tSide` | 否 | 起/止接入边：`top` `right` `bottom` `left` |
| edge | `sRatio` / `tRatio` | 否 | 在该边上的位置，0–1（0=起点端，1=终点端） |
| edge | `arrow` | 否 | `true` 才画箭头 |
| edge | `dashed` | 否 | `true` 画虚线 |
| edge | `sourcePort` / `targetPort` | 否 | 一般不要写，由编辑器自动维护 |

不写 `sSide`/`tSide` 时，编辑器按几何自动选最近边；**手工写的值优先**，用来钉死走向。

## 三、层与配色

层由颜色表达，**不画层带边框、不限制节点位置**。numas 现有约定（与 `numas/AGENTS.md` 一致）：

| 层 | 语义 | 颜色 |
| --- | --- | --- |
| `local` | 本地服务（跑在用户机器上） | 紫 `#c084fc` |
| `app` | webapp / 对外入口模式 | 蓝 `#58a6ff` |
| `edge` | 接入层（公网入口） | 琥珀 `#fbbf24` |
| `svc` | 应用层业务服务 | 粉 `#f472b6` |
| `infra` | 基础设施（集群、调度） | 绿 `#34d27b` |

配色是数据驱动的：想换色改 `bands[].color` 即可，节点会自动跟随。

## 四、布局约定

- 画布 1600×900；节点高默认 72；同层 `y` 对齐。
- 纵向层间距 160–190；横向节点间距 ≥ 40。
- 宽节点（如 ingress）横跨多个下游时，接入点按**对端中心的投影**取，不要永远取边中点。
- 层从上到下：入口模式 → 接入层 → 应用层 → 基础设施层；本地链路单独一侧。

## 五、布线约束（必须满足）

只有**水平/垂直直线**与**圆角折线**，没有斜线、没有贝塞尔曲线：

1. 接入点必须落在节点**边上**，不能落在内部
2. 首段/末段**垂直于所连的边**：左右边横进横出，上下边竖进竖出
3. 折数越少越好，能不折就不折；绕不开也保持正交
4. 优先不穿过其它节点；实在绕不开接受穿过，但不要重叠节点
5. **只有条件分支才画箭头**（`arrow: true`）；入口、承载、路由关系不带箭头
6. 虚线（`dashed: true`）表示非主链路/可选路径，别和箭头混用来表达同一件事
7. 宽节点按对端中心投影取点，避免长距离绕行

编辑器会自动重算正交路径，手工写的 `sSide`/`sRatio` 只是钉住接入位置；所以**先把节点的相对位置摆对**，线自然会好看。

## 六、自检（交付前必跑）

```bash
node apps/skills/panorama/scripts/check.mjs <文件.pano>
```

检查内容：YAML 可解析、字段齐全、id 唯一、band 引用存在、边两端存在、`sSide`/`tSide` 合法、`ratio` 在 0–1、节点是否越出画布、节点是否互相重叠。

输出 `PASS` 才算交付；`FAIL` 会指出具体节点/边。

## 六之二、现成示例

`apps/examples/panorama/` 下有两个可直接打开、且已通过自检的文件，优先照着改：

| 文件 | 用途 |
| --- | --- |
| `hello.pano` | 最小可运行（2 节点 / 1 连线），确认链路用 |
| `webapp.pano` | 分层 Web 应用（接入层 → 应用层 → 基础设施层），含条件分支箭头 |

## 七、常见错误

| 现象 | 原因 |
| --- | --- |
| 打开后一片空白 | YAML 解析失败（缩进、tab 字符、中文冒号） |
| 节点没有颜色 / 图例少一项 | `node.band` 引用了不存在的 band id |
| 连线指向空气 | `edge.from` / `edge.to` 拼错，或节点 id 改了没同步 |
| 线斜着走 | 手工动了 `sSide` 与节点位置组合，导致无法正交；删掉这两个字段让编辑器重算 |
| `y` 字段看起来被加引号 | 正常：js-yaml 会把 `y` 键写成 `'y'`（YAML 1.1 里 y 容易与布尔混淆）；两种写法都能读 |
| 改动没生效 | 文件没保存；插件的自动保存是改动后 600ms 写回，外部改文件需要重新打开或等推送 |

## 八、交付检查单

- [ ] 后缀是 `.pano`（或 `.panorama`）
- [ ] `check.mjs` 输出 PASS
- [ ] 每层有 `label`，图例能读懂
- [ ] 箭头只出现在条件分支
- [ ] 节点不重叠、不越界
- [ ] 在 numas 里打开确认渲染（命令面板 `Numas: 打开全景图`，或直接双击文件）
