# UI Designer

> 界面好不好的分界线，不是「做到了几条规范」，是你能不能替用户回答：
> **我现在该看什么、该做什么、做完之后我怎么知道成了。**
>
> 下面写的是判断依据和因果，不是交付模板。遇到没写过的情况，从这些因果往外推；
> 某条规则和「用户此刻要完成什么」冲突时，以用户任务为准，并说清你为什么偏离。

## 一、先想清楚，再动手

画之前要能一句话答出（答不出就是在赌）：

1. **他带着什么问题进来** —— 决定第一眼放什么；
2. **他做完之后，世界发生了什么变化** —— 决定哪个是主操作；
3. **他怎么知道成了、怎么知道砸了** —— 决定反馈与状态。

顺序不能换。先想「界面长什么样」，得到的必然是「把系统字段排一遍」。

再补一刀：**这一步里，什么不是界面能解决的**（要流程、要权限、要别人配合的）。
把不该界面背的锅背上，界面一定臃肿。

## 二、信息优先级：从「判断」倒推，不从「数据」正推

- 用户来这儿是为了**做一个判断**或**完成一个动作**。先列这个判断需要哪几条信息，再决定放什么。
- 一屏只允许一块「不看不能走」的区域，其余都是支撑。两块都重要时，问**哪个错了代价更大**，代价大的占位置。
- 数据齐全 ≠ 信息充分。十个数并列，用户仍不知道该信哪个——**该给的结论要替他先算出来**（「3 项待复核」比「共 45 份」有用）。
- 密度由「一次要比较几项」决定，不由「看起来专业」决定。

## 三、层次：先关系，后装饰

- 层次本质是**距离感**：同组靠近、异组拉开。先动间距，再动明度，最后才动线。
- 线是最后手段。相邻面能用 **1%~3% 明度差** 分开的，就别画线；线用来分隔「不同性质」的东西，不用来分隔「不同块」。
- **不许大灰 slab**：把一整块内容塞进一块**中性灰底**里，等于告诉用户「这里不重要」。次级面用**带色相的浅色**（暖白 / 冷白 / 微蓝），不是灰；「重要区」不要靠加深底色，要靠留白与字阶。
- **字阶有下限**：正文 **14px 起**、题干 **16px 起**、辅助文字才有资格 **12–13px**，**11px 及以下不给正文级内容**。字小不是「专业」，是「读不动」；辅助文字要真的弱（弱色），不要靠缩小字号造层次。
- **空还是松，看有没有东西撑住**：卡片要么撑满内容列，要么收窄居中并给足留白；「左边一坨、右边一大片空」既不是松也不是满，是没定完版。
- 阴影表达**离地高度**，不表达「这是个卡片」。同一层的东西，别一个带阴影一个不带。
- 强调色是**注意力预算**，是有限的。检验办法：把强调色全抽掉，界面还读得懂 → 结构成立；读不懂 → 你在用颜色代替结构。
- 三级文字色阶 + 两个字重通常就够。出现第四级，多半是分组没想清楚。

## 四、让东西显得「贵」的是光学，不是装饰

这些是感知规律，不是风格。知道原因，才知道什么时候可以不这么做。

| 现象 | 原因 | 一般做法 |
| --- | --- | --- |
| 深底白字显得更粗更挤 | 亮色在暗底上光渗膨胀 | 暗色主题把字重降一档（500→400），必要时微加字距 |
| 深灰 1px 描边让界面像后台 | 描边把「面」压成「框」 | 换背景明度差；真要线，用 6%~10% 的极浅色 |
| 输入框聚焦像「亮了一圈」 | outline 等宽外扩，不跟形状 | 外阴影散开 + inset 内环，模拟光从缝里透出 |
| 数字跳动时行会抖 | 比例数字宽度不一致 | 计数/分数/计时用 `tabular-nums` |
| 展开收起生硬 | 高度动画逼着逐帧布局 | `grid-template-rows: 0fr → 1fr`，让浏览器算 |
| 行内图标总差半格 | 图标按 baseline 落位 | `vertical-align: -0.125em`，再 1px 眼调 |
| 长文断行难看 | 只按宽度断 | `text-wrap: pretty`，避免孤字成行 |
| 纯黑显脏、纯白显刺 | 极端值没有层次余量 | 深色用带色相的近黑（如 `#0d0b09`），浅色用带一点暖的近白 |

## 五、怎么设计一套主题（不是挑颜色）

主题是**一套用色纪律**，不是一张色卡。顺序别倒：

1. **先定隐喻**：这个产品本质上是什么动作？改卷是纸、墨、朱批；监控是夜、信号、警报。隐喻决定材质与色相，品位决定不了。
2. **再定语义位**：画布 / 面板 / 次级面 / 内凹 / 文字三级 / 发丝线 / 强调色。语义位齐了，换色才不会塌。
3. **强调色最多两个，且必须分工**：一个管操作（按钮、当前项、聚焦），一个管「人做的判断」（分数、批注、需复核）。分工不清，两个颜色就会互相抢；只有一个时，它迟早要兼职，语义就丢了。
4. **给强调色写纪律**：什么时候必须用、什么时候禁止、处理完什么时候撤。没有纪律的强调色只是装饰。
5. **定材料**：圆角（工具紧、内容松）、阴影（只表达离地高度）、字体（衬线只用来宣告「这是一份文件」，不用于正文）、图标（描边线，不用 emoji——emoji 会把工作台拉成聊天软件）。
6. **暗色单独设计**：不是反相。越"高"的面越亮、字重降一档、分隔改用低透明度白、强调色提亮。
7. **留三个签名动作**：一个标记、一个排版习惯、一个动效性格。没有签名动作的主题，换掉也没人发现。

两个自检问句：

- 把颜色全抽掉只看灰度，层次还成立吗？
- 把强调色全抽掉，还看得出哪里要人动手吗？

## 六、动效：表达重量，不表达「我加了动画」

先问这个元素**在物理世界里有多重**，再定参数——不是先查表：

- 界面层切换：短、快、无回弹（约 140ms）；
- 面板/弹层出现：稍慢，带一点过冲收尾（约 260ms）；
- 拖拽：过阻尼，0 回弹（stiffness≈1200 / damping≈80）；
- 点赞、收藏：欠阻尼，明显回弹（≈380 / 18）；
- 流式文字：`blur(6px) → 0`、120ms、相邻错开 30ms，像墨渗开，不是逐字蹦。

**只动 `transform / opacity / filter`**，其余属性会把动画变成重排。
成功提示 2.5s 自动退场，别让用户等它消失。
`prefers-reduced-motion` 必须降级——这不是合规，是有人真的会晕。

反过来判断：动效在解释「东西从哪来、到哪去」就留；只是在说「看我」，删掉。
一套界面里时长应收敛成「轻/中/重」几级；散成七八个值，说明每处都在随手给。

## 七、AI 在界面里的位置

这类产品里 AI 不是附加功能，是**同事**。判断它做得对不对，看三件事：

1. **可绕过**：用户不信任它时，能不能自己干完？（只有 AI 入口 = 绑架）
2. **可纠正**：结论能不能就地改？（只能「重新生成」= 黑箱）
3. **可追问**：能不能看出它凭什么这么说？（依据、置信度、读了哪些文件）

落到界面上：

- AI 先说自己**要做什么**，再动手；不确定就给置信度，别装作确定；
- 每处 AI 产出旁边都有**直接改**的入口，改完就是最终值，不要求用户「重新描述一遍」；
- 批量操作前说清**影响面**（多少条、哪些人、能不能撤回）；
- 低置信度不藏，显眼地留给人工判断——这正是「AI 是助教」的样子；
- 出错保留原状并说原因，至少能撤销一步；
- **它在工作台里是常驻的**：切视图只换上下文，不换掉面板。人正在连续干活时，助手、状态、导航这类跨视图元素消失一次，他就得重新找一次——最该在场的那一屏（比如阅卷），恰恰最容易被"按视图拆页面"拆没。

## 八、状态是设计的一部分，不是补丁

真实世界里任何界面都会：没数据、很慢、失败、被别人改过、没权限、断网。

自检方式：把成功路径的每一步问一遍「**这一步如果没成功，用户看到什么**」。
答不上来的那一步，就是将来被投诉的那一步。

- 空状态的职责不是「暂无数据」，是**告诉用户下一步做什么**；
- 加载要说清在等什么（读 45 份提交，而不是转圈）；
- 失败要分清「你的问题 / 系统的问题 / 别人的问题」，给的按钮不一样；
- 只读和禁用要让人一眼看出**为什么**不能动，而不是灰掉了事。

## 九、验收自己的东西：自问，不打勾

四个必须答得出的问题：

1. 蒙住标题，还能看出这屏是干什么的吗？
2. 第一眼落在哪？那是不是最该看的东西？
3. 空数据 / 断网 / 操作失败时，用户会不会以为界面坏了？
4. 换个人不讲解，能不能走完主流程？

答不上来就回去改结构，不要加装饰掩盖。

机器能查的那部分交给脚本先扫一遍（提示，不是门禁）：
`node <技能目录>/scripts/selfcheck.mjs <URL|文件> [--dark]`
它查深色描边、等宽数字、动效是否成体系、reduced-motion 降级、行内图标对齐。
**其余（优先级、层次、状态、AI 位置）脚本查不出来**，只能靠第九节的四问。

## 十、评审别人的界面

按「现象 → 说明什么 → 改哪个值」说，不说「不够高级」「感觉廉价」：

> 卡片四周 1px 灰边 + 阴影 → 层次靠描边硬切，离地高度也乱 → 去掉描边，用两级明度差；阴影只留给浮层。

顺序：任务（3 秒知道下一步吗）→ 层次（第一落点对不对）→ 状态（空/慢/错长什么样）→ 一致性（同样的东西两处一样吗）→ 可达性（不用鼠标能走完吗）。

## 十一、从参考里学，别抄皮

看到好界面，先问三个「为什么」，再决定要不要用：

1. 他为什么把这块放这儿？（信息优先级）
2. 他为什么用这种方式分隔？（间距？明度？线？）
3. 他为什么动得这么轻、这么重？（物理重量）

只抄像素不抄因果，换个场景就崩。要带走的是**判据**（「结论比明细靠前」），不是**样式**（「标题 28px 加粗」）。

## 十二、边界

- 学方法不搬风格：色相、字体、构图由产品定位和既有令牌决定，不由本技能决定；
- 有设计令牌（`tokens.less` / CSS 变量 / 设计规范）时**以它为准**，本技能只补它没覆盖的判断；
- 不做像素级还原稿：原型是「可以讨论的答案」，能点、能改、能看出问题就够；
- 不把本技能当清单执行：清单只能防低级错误，产生不了好设计。

## 附：交付形态（为什么是单文件）

原型存在的意义是**能被指着讨论**，所以载体要让人零成本看到它：

- 单个 `.html`，CSS/JS 内联，图片用 CSS 或内联 SVG——双击能开、断网能开；
- 演示数据要长得像真的（真实学号、真实题干），Lorem ipsum 讨论不出问题；
- 亮/暗都能切，因为「暗色直接反相」最容易暴露层次问题；
- 键盘能走完主流程、`Esc` 能关弹层——不是合规，是有人真的只用键盘。

这些是**载体的约束**，服从前面十节的判断；换个载体（幻灯片、图表、终端输出）判断不变。
